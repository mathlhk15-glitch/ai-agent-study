      2진짜 차이는 이것이다

      흔히 다음과 같이 설명합니다.

      간단한 일 → Chat
      복잡한 일 → Work

      또는

      답이 필요 → Chat
      파일이 필요 → Work

      하지만 둘 다 완전히 정확한 기준은 아닙니다.

      Chat도 복잡한 분석을 할 수 있고 파일을 사용할 수 있으며, Search도 여러 출처를 조사할 수 있습니다.

      더 정확한 기준은 이것입니다.

      대화형

      사람이 계속 AI와 주고받으며 일을 이끌어 간다.

      이것 설명해 줘.
      이렇습니다.
      조금 더 쉽게.
      이렇게 바꾸겠습니다.
      표로 만들어 줘.

      → 사람이 한 단계씩 방향을 잡습니다.

      에이전트형

      사람은 목표와 조건을 주고, AI가 여러 실행 단계를 주도한다.

      이 설문 3개와 작년 보고서를 분석해서 올해 결과보고서와 발표자료를 만들어 줘.
      자료 확인→분석→계산→비교→표 작성→그래프 작성→보고서 작성→발표자료 제작

      → AI에게 실행 주도권을 더 많이 맡깁니다.

      따라서 가장 오래 기억할 기준은

      “내가 AI와 대화를 이끌어 갈 것인가, 목표를 주고 여러 단계의 일을 맡길 것인가?”

      입니다.

      구분 기준정확도왜 그런가
      간단한 일 vs 복잡한 일부분적Chat도 복잡한 분석을 하고, Search도 다중 출처 조사를 한다
      답 vs 파일부분적Chat에서도 파일을 읽고 결과물을 만들 수 있다
      대화 주도 vs 실행 위임가장 정확누가 다음 단계를 결정하느냐는 제품이 바뀌어도 유지된다

      3ChatGPT : Chat vs Work

      ① Chat — “옆자리의 똑똑한 동료”

      Chat은 우리가 평소 사용하는 ChatGPT입니다.

      질문하고 대답을 받으면서 함께 문제를 해결합니다.

      예를 들어

      • “고교학점제를 초등학생도 이해하게 설명해 줘.”
      • “이 안내문을 학부모가 읽기 쉽게 고쳐 줘.”
      • “이 PDF에서 중요한 내용만 찾아 줘.”
      • “두 자료를 비교해 줘.”

      와 같은 일을 할 수 있습니다.

      즉,

      질문→답→수정 요청→다시 답

      이라는 방식이 중심입니다.

      ② Work — “업무를 통째로 맡는 조교”

      Work는 목표와 결과물을 주면 AI가 필요한 여러 단계를 스스로 계획하고 실행하는 쪽에 초점을 둡니다.

      예를 들어

      “학생 설문 Excel 3개와 작년 결과보고서를 분석해서
      올해 진로교육 운영 결과보고서를 작성하고
      표와 그래프를 넣은 발표자료까지 만들어 줘.”

      라고 할 수 있습니다.

      이 경우 Work는

      자료 확인→분석→계산→문서 작성→표·그래프 제작→최종 결과물

      같은 작업을 이어서 수행할 수 있습니다.

      OpenAI는 Work를 앱·파일·브라우저 등을 활용해 장시간·다단계 작업을 수행하는 환경으로 제공하고 있습니다.

      추가OpenAI 공식 도움말은 Work의 용도를 “주제 조사, 정보 분석, 문서·스프레드시트·프레젠테이션·보고서·Site(웹페이지) 제작”으로 적고 있습니다. 또 Work와 Codex에서만 쓰는 전용 모델(GPT-6 Sol, GPT-6 Luna 등)이 있어 일반 Chat에서는 쓸 수 없고, Work의 사용량은 Chat과 별도로 Codex와 같은 허용량 구조에서 차감됩니다.

      Work는 웹에서도 일을 할 수 있다

      Work에는 웹 작업 기능도 있습니다.

      클라우드 브라우저를 이용하면 지원되는 사이트에서

      • 웹페이지 읽기
      • 링크 이동
      • 버튼 클릭
      • 양식 입력
      • 여러 페이지 조사

      등을 수행할 수 있습니다.

      사용자의 로그인이나 확인이 필요한 순간에는 작업을 멈추고 사용자의 입력이나 승인을 요구할 수 있습니다.

      데스크톱 앱에서는 별도의 내장 브라우저를 이용해 더 직접적인 웹 작업도 가능합니다.

      따라서

      “웹 검색 결과를 알려 줘.”

      “사이트들을 돌아다니며 필요한 자료를 수집하고 정리해서 보고서를 만들어 줘.”

      의 차이라고 생각하면 쉽습니다.

      중요한 사실 ① “Chat은 파일을 못 쓰고 Work만 파일을 쓴다” → 틀린 구분

      파일 사용 여부는 핵심 차이가 아닙니다.

      Chat도 업로드 파일이나 지원되는 연결 파일 서비스를 활용할 수 있습니다.

      따라서

      틀림Chat = 파일 사용 불가
      맞음Chat = 대화 중심
      틀림Work = 파일을 쓰는 기능
      맞음Work = 여러 단계의 업무 위임 중심

      이라고 이해하는 것이 좋습니다.

      첨부 자료에서도 이 점을 명확히 지적하고 있습니다.

      추가 근거2026년 9월 10일부터 Box·Dropbox·SharePoint가 Google Drive와 함께 ChatGPT Library에 들어왔고, 웹의 Chat과 Work 양쪽에서 쓸 수 있습니다. 폴더를 선택해 그 안의 파일 전체를 대상으로 작업하는 것도 가능합니다. (Go·Plus·Pro·Business·Edu·Healthcare·Enterprise 대상 순차 배포)

      중요한 사실 ② ChatGPT Work도 내 컴퓨터 파일을 사용할 수 있다

      ChatGPT 데스크톱 앱의 Work에서는 사용자가 로컬 폴더나 프로젝트에 권한을 주면 그 안의 파일을 사용할 수 있습니다.

      반면 웹·모바일의 Work는 사용자의 PC 파일에 직접 접근하지 않습니다.

      또 중요한 점은 로컬에서 작업하더라도 메시지와 작업 맥락 일부는 클라우드에 저장될 수 있다는 것입니다.

      따라서

      “로컬 파일 작업 = Claude만 가능”

      이라고 설명하면 현재는 틀립니다.

      ChatGPT Work 실행 위치웹모바일데스크톱 앱
      실행 방식클라우드클라우드클라우드 또는 로컬
      내 PC 파일 직접 접근✕✕○ (권한 부여 시)
      데스크톱 앱 사용✕✕○ (권한 부여 시)
      기기 간 이어하기○○클라우드 작업만

      추가 표: OpenAI 도움말 기준. 요금제·조직 설정에 따라 다를 수 있습니다.

      중요한 사실 ③ Work ≠ Scheduled Tasks

      Work와 Scheduled Tasks는 같은 기능이 아닙니다.

      Work

      일을 수행하는 업무 환경

      Scheduled Tasks

      그 일을 언제 실행할지 정하는 자동화 기능

      예를 들어

      “매주 월요일 오전에 새로운 자료를 확인해 줘.”

      처럼

      • 한 번 실행
      • 일정에 맞춰 반복
      • 특정 변화 감지
      • 이벤트 기반 실행

      등을 설정할 수 있습니다.

      Work는 Scheduled Tasks와 결합해 반복·모니터링 업무도 수행할 수 있습니다.

      즉,

      Work = 직원
      Scheduled Tasks = 직원에게 주는 근무 일정

      이라고 생각하면 쉽습니다.

      추가“이벤트 기반 실행”의 공식 예시는 새 Gmail 메일 도착, 새 Slack 채널 메시지, GitHub 풀 리퀘스트 활동입니다. Free·Go 요금제에서는 이벤트 기반 작업을 쓸 수 없습니다.

      중요한 사실 ④ ChatGPT에는 Codex도 있다

      ChatGPT 데스크톱 환경에는 Codex라는 별도의 개발용 작업 환경도 있습니다.

      Codex는 특히

      • 프로그램 코드 작성
      • 디버깅
      • 저장소 작업
      • 터미널과 개발 도구 사용

      등 소프트웨어 개발 업무에 특화되어 있습니다.

      현재 OpenAI는 Chat / Work / Codex를 서로 다른 작업 경험으로 구분하고 있으며, Codex는 별도 뷰와 별도의 작업 기록을 사용합니다.

      초보자가 기억할 필요가 있는 수준으로 줄이면

      모드한 줄 정의대표 작업
      Chat대화질문, 검색, 아이디어, 빠른 도움
      Work일반 업무 수행조사·분석, 문서·표·발표자료·Site 제작
      Codex개발 업무 수행코드 작성·디버깅, 테스트, 저장소 작업

      입니다.

      추가Codex Cloud를 쓰면 웹·모바일에서도 코딩 작업을 시작하고 이어갈 수 있습니다. 즉 “Codex = 데스크톱 전용”이라고 외우면 불완전합니다.

      4Claude : Chat vs Cowork

      여기에는 2026년 9월 말 현재 매우 중요한 변화가 있습니다.

      원래는

      Claude에는

      Chat

      대화하면서 질문하고 답을 받는 공간

      Cowork

      복잡한 일을 여러 단계에 걸쳐 맡기는 업무 환경

      이 따로 있었습니다.

      그런데 현재 Anthropic이 이 구조를 바꾸고 있습니다.

      가장 중요한 최신 변화: “Chat과 Cowork가 하나의 Claude로 합쳐지는 중”

      Anthropic은 현재 Chat과 Cowork의 구분을 없애는 새로운 Claude 경험을 Pro·Max부터 단계적으로 배포하고 있습니다.

      새 환경에서는 사용자가

      “Chat으로 할까, Cowork로 할까?”

      를 먼저 고를 필요가 없습니다.

      그냥 Claude에게

      “이것 설명해 줘.”

      라고 하면 짧게 답하고,

      “이 파일들을 분석해서 보고서와 PPT를 만들어 줘.”

      라고 하면 Claude가 필요한 도구를 선택해서 업무를 수행합니다.

      Anthropic은 이를 공식적으로 “Claude Cowork and chat are one Claude”라고 설명하고 있습니다.

      따라서 앞으로는

      예전 설명Claude Chat vs Cowork
      오래가는 설명Claude가 요청을 보고 ‘대답할지, 일을 수행할지’ 판단한다

      라고 이해하는 것이 더 오래가는 설명입니다.

      아직 새 환경이 적용되지 않은 일부 계정에서는 기존의 Chat/Cowork 선택지가 그대로 보일 수 있습니다.

      추가구분법: Pro·Max 요금제인데 메시지 입력창에 “Chat”과 “Cowork” 선택지가 보이지 않는다면 새 경험이 적용된 것입니다. Chrome 사이드패널에서 Claude를 열면 선택지 없이 바로 Cowork 세션이 시작됩니다.

      Claude의 업무형 동작은 무엇을 할까?

      예를 들어 이렇게 요청합니다.

      “이 다섯 개의 인터뷰 기록을 읽고 공통 주제를 찾아서 보고서를 만들고, 그 내용을 10장짜리 발표자료로 바꿔 줘.”

      Claude는

      • 파일 읽기
      • 웹 검색
      • 코드 실행
      • 자료 분석
      • 보고서 작성
      • 스프레드시트 작성
      • 프레젠테이션 제작

      등을 하나의 작업으로 이어갈 수 있습니다.

      작업이 길어지면 클라우드에서 계속 실행될 수도 있습니다.

      추가공식 기능 설명에는 복잡한 일을 작은 작업으로 나눠 동시에 처리하는 “하위 에이전트 조율”, 대화 시간 제한에 끊기지 않는 “장시간 작업”이 포함됩니다. 예약 작업은 입력창에 /schedule을 입력하거나 왼쪽 사이드바의 “Scheduled”에서 만듭니다.

      Claude는 데스크톱 전용인가?

      아닙니다.

      현재 Cowork 기능은

      • 데스크톱
      • 웹
      • 모바일
      • Claude in Chrome

      등에서 제공되고 있습니다.

      세션과 파일도 Claude 계정에 연결되어 여러 기기에서 이어볼 수 있습니다.

      다만 내 컴퓨터에 있는 실제 파일이나 브라우저, 앱을 사용하려면 데스크톱 앱의 역할이 여전히 중요합니다.

      새로 중요한 축클라우드에서 할 일 vs 내 컴퓨터를 이용해야 할 일

      구분도 중요합니다.

      클라우드 작업

      Anthropic 서버에서 실행됩니다.

      예:

      • 웹 조사
      • 업로드 자료 분석
      • 보고서 제작
      • 스프레드시트 제작
      • 프레젠테이션 제작
      • 예약 업무

      컴퓨터를 닫아도 계속 진행할 수 있습니다.

      내 컴퓨터가 필요한 작업

      예:

      • PC의 특정 폴더 읽기·쓰기
      • 로컬 파일 수정
      • 데스크톱 앱 사용
      • 화면 직접 클릭
      • 로컬 브라우저 사용

      이런 작업에는 Claude Desktop이 필요하며, 관련 기능을 쓰는 동안 데스크톱 앱이 열려 있어야 할 수 있습니다.

      추가2026년 10월 6일부터 Pro·Max 요금제의 새 Cowork 작업은 클라우드에서 실행되고, 설정의 “내 컴퓨터에서만” 옵션이 사라집니다. 이미 내 컴퓨터에서 시작한 작업은 그대로 남습니다. 폴더 자체는 계속 내 컴퓨터에 있고, 작업에 필요한 파일이 있으면 그 파일의 사본만 가져갑니다. 세션을 삭제하면 가져간 사본도 함께 삭제됩니다. 작업을 반드시 한 컴퓨터 안에서만 돌려야 한다면 Anthropic은 데스크톱 앱의 Claude Code를 대안으로 안내합니다.

      Claude는 컴퓨터 화면도 직접 사용할 수 있다

      Claude에는 Computer Use 기능이 있습니다.

      필요한 경우 화면에서 직접

      • 클릭
      • 타이핑
      • 앱 실행
      • 화면 이동

      등을 수행할 수 있습니다.

      이것은 폴더 접근이나 커넥터와는 다른 형태의 권한입니다.

      따라서

      “특정 폴더만 허용했으니 Claude가 컴퓨터의 다른 것은 절대 볼 수 없다.”

      처럼 단순하게 이해하면 안 됩니다.

      어떤 기능을 켰는지를 함께 확인해야 합니다.

      추가Computer Use는 Pro·Max에서 베타입니다. 휴대폰에서 지시하면 켜져 있는 내 데스크톱에서 작업하는 “Dispatch” 기능도 있으며, 이때는 컴퓨터가 깨어 있고 Claude Desktop 앱이 열려 있어야 합니다.

      Claude의 브라우저 기능

      Cowork 계열 업무에서는 Claude가

      • Claude Desktop의 내장 브라우저
      • Claude in Chrome

      등을 사용할 수 있습니다.

      내장 브라우저에서는 Claude가 사이트를 열고, 읽고, 클릭하고, 입력할 수 있습니다.

      따라서 Claude도 단순 파일 작업만 하는 것이 아니라 웹 기반 업무까지 수행할 수 있습니다.

      Cowork ≠ Artifacts

      이 부분은 반드시 구분해야 합니다.

      Artifacts

      Claude가 만든

      • 문서
      • 코드
      • 웹페이지
      • 도표
      • 인터랙티브 결과물

      등을 화면에서 보고 수정하는 결과물 공간에 가깝습니다.

      Cowork

      파일·도구·웹·앱 등을 활용해서 업무 자체를 수행하는 방식입니다.

      따라서

      Artifacts = 결과물을 보여주는 그릇
      Cowork = 일을 수행하는 방식

      정도로 이해하면 쉽습니다.

      그리고 현재는 Cowork에서 만든 Artifact도 일반 Artifact 체계와 함께 사용할 수 있습니다. Anthropic은 2026년 8월 19일 이후 Cowork에서 만들어진 Artifact가 다른 Artifact와 같은 방식으로 동작한다고 안내합니다.

      Projects도 Cowork와 다르다

      Claude Projects는

      • 관련 파일
      • 지침
      • 작업
      • 문맥

      등을 한 공간에 묶어 놓는 지속적인 작업 공간입니다.

      즉,

      Projects = 서류철·업무실
      Cowork/업무형 Claude = 그 안에서 일하는 직원

      정도로 보면 이해하기 쉽습니다.

      Claude 용어비유하는 일
      Chat상담 창구대화하며 질문하고 답을 받음
      Projects서류철·업무실관련 파일·지침·작업·문맥을 한곳에 묶음
      Artifacts결과물 그릇만든 문서·코드·웹페이지를 보고 수정
      Cowork일하는 직원파일·도구·웹·앱으로 여러 단계 업무 수행
      Scheduled근무 일정표작업을 정해진 때 자동 실행
      Computer Use직원의 손화면을 직접 클릭·입력·이동

      추가 표: Claude 용어 한눈에 정리

      추가프로젝트에서 Chat이나 Cowork 세션을 시작하면 Claude가 프로젝트 지식을 맥락으로 씁니다. 다만 Cowork는 프로젝트 내용을 직접 바꾸지 않으므로, 남기고 싶은 결과물은 사용자가 프로젝트에 추가해야 합니다.

      5Perplexity : Search vs Computer

      Perplexity는 세 회사 중 구분이 가장 명확합니다.

      공식 설명은

      Search = Understanding
      Computer = Execution

      입니다.

      쉽게 번역하면

      Search = 알아보기
      Computer = 실행하기

      입니다.

      ① Search — “출처를 찾아주는 사서”

      Perplexity Search에서는 질문하면 인터넷 자료를 찾아

      • 자료 조사
      • 요약
      • 비교
      • 설명

      을 하고 출처를 함께 보여 줍니다.

      예를 들어

      “2028학년도 서울대 전형 변경사항을 공식 자료를 중심으로 정리해 줘.”

      라고 하면 관련 웹 자료를 조사해 답을 만듭니다.

      따라서 Search의 결과물은 주로

      출처가 붙은 답변

      입니다.

      Search도 어려운 조사를 할 수 있다

      중요합니다.

      틀림Search = 간단한 질문만 가능
      맞음Search도 복잡한 다중 출처 조사가 가능

      은 아닙니다.

      Perplexity는 Search도

      • 여러 출처 비교
      • 복잡한 질문
      • 조사형 질문
      • 첨부 파일 활용

      등을 처리할 수 있다고 설명합니다.

      따라서

      간단한 질문 = Search
      어려운 질문 = Computer

      로 구분하면 안 됩니다.

      추가Perplexity 공식 예시: 엔비디아의 3~5년 현금흐름할인(DCF) 모델을 만들고 실시간 시장 데이터로 AMD·브로드컴과 비교하는 일을 Search의 출처 달린 답변 한 번으로 처리합니다. 또 Search는 구독에 포함된 프리미엄 출처와 연결된 지식에서도 결과를 가져올 수 있습니다.

      ② Computer — “디지털 직원”

      Computer는 Perplexity가 실행형 작업을 위해 제공하는 기능입니다.

      예를 들어

      “경남지역 대학의 2028 신설학과를 조사해서
      대학별 비교표를 만들고
      보고서와 발표자료를 만들고
      이후 변경사항도 정기적으로 확인해 줘.”

      처럼 요청할 수 있습니다.

      Computer는

      조사→분석→자료 결합→파일 제작→외부 도구 활용→반복 실행

      까지 이어갈 수 있습니다.

      Perplexity는 Computer를 다단계·다도구 업무에 사용하는 기능으로 설명하며, 보고서·스프레드시트·프레젠테이션·대시보드·웹사이트 같은 결과물을 만들 수 있다고 안내합니다.

      Perplexity 공식 선택 기준

      Search를 쓸 때Computer로 넘어갈 때
      답 자체가 결과물일 때여러 앱이나 연결 도구를 오가야 할 때
      맥락이 질문이나 첨부 파일 하나에 다 들어갈 때일정에 따라 실행하거나 변화를 계속 감시해야 할 때
      출처 달린 한 번의 답으로 충분할 때보고서·스프레드시트·발표자료·대시보드처럼 여러 자료로 만든 완성품이 필요할 때
      —일을 완성·반복·포장·전달해야 할 때

      추가 표: Perplexity Academy “Search vs Computer” 기준

      Computer는 여러 앱을 연결한다

      Perplexity는 Computer가 다양한 외부 애플리케이션 및 도구와 연결될 수 있다고 설명합니다.

      공식 예에는

      • Google Drive
      • Slack
      • Salesforce
      • GitHub
      • Snowflake

      등이 있고, 전체적으로 400개 이상의 연결을 언급하고 있습니다.

      다만 연결 가능한 서비스와 권한은

      • 요금제
      • 조직 설정
      • 계정 권한
      • 출시 시점

      등에 따라 달라질 수 있으므로 실제 계정에서 확인하는 것이 안전합니다.

      추가이용 조건: Perplexity 공식 제품 페이지 기준 Computer는 Pro와 Max 구독자가 데스크톱·모바일·Slack·Microsoft 365에서 쓸 수 있으며, 작업 실행에 크레딧을 소모합니다. 출시 초기에는 Max(월 200달러) 전용이었고, 당시 Max에는 매월 10,000크레딧이 포함되었습니다.

      Computer는 여러 AI를 조합한다

      Computer는 하나의 AI 모델만 이용하는 구조가 아닙니다.

      작업 성격에 따라 여러 모델과 하위 에이전트를 조합하는 다중 모델 오케스트레이션 방식을 사용합니다.

      따라서

      “Computer에는 AI가 정확히 19개 있다.”

      처럼 외우는 것은 좋지 않습니다.

      출시 이후 모델 구성과 수는 계속 바뀔 수 있기 때문입니다.

      공부할 때는

      Computer = 여러 전문 AI를 작업에 맞게 조합하는 구조

      정도로 기억하는 것이 더 정확합니다.

      참고: 19개는 2026년 2월 출시 발표 당시의 수치입니다. 이 구조는 더 나은 모델이 나오면 교체하도록 설계되어 있습니다.

      Computer ≠ Deep Research

      이것도 자주 혼동합니다.

      Deep Research

      주로 깊이 조사하는 것이 목적입니다.

      Computer

      조사를 넘어

      • 결과물 제작
      • 앱 연결
      • 도구 사용
      • 반복 업무
      • 일정 실행
      • 변화 모니터링

      등까지 포함합니다.

      따라서

      Deep Research = 깊이 조사
      Computer = 조사하고 실제 일까지 수행

      이라고 이해하는 것이 좋습니다.

      Perplexity 단계깊이자율성결과물
      Search빠른 출처 답변낮음출처 달린 답변
      Pro Search더 많은 출처 수집·종합낮음~중간출처 달린 답변

      Perplexity는 Personal Computer라는 기능도 제공하고 있습니다.

      7“로컬 vs 클라우드”도 함께 이해하자

      앞으로 에이전트형 AI를 이해할 때 매우 중요한 두 번째 기준입니다.

      클라우드 실행

      AI 회사의 서버에서 작업합니다.

      장점:

      • 내 컴퓨터를 꺼도 계속할 수 있음
      • 휴대폰에서 진행 상황 확인 가능
      • 여러 기기에서 이어서 작업 가능

      로컬 접근

      내 PC의

      • 폴더
      • 파일
      • 프로그램
      • 브라우저
      • 화면

      등을 사용합니다.

      장점:

      • 실제 컴퓨터 업무와 직접 연결 가능

      주의:

      • 개인정보와 권한 관리가 훨씬 중요함
      한 가지 더: “로컬에서 실행”이 곧 “데이터가 밖으로 안 나간다”는 뜻은 아닙니다. ChatGPT는 로컬 작업이라도 메시지와 작업 맥락이 클라우드에 저장될 수 있다고 안내하고, Claude는 10월 6일 이후 작업에 필요한 파일의 사본을 클라우드로 가져간다고 안내합니다.

      ① 목표무엇을 완성할 것인가?
      ② 자료어떤 파일·폴더·사이트를 사용할 것인가?
      ③ 범위무엇을 포함하고 제외할 것인가?

      ⑥ 형식분량·표·그래프·문체 등은 어떻게 할 것인가?

      “첨부한 설문 Excel 3개와 작년 결과보고서를 이용해 올해 진로교육 운영 결과보고서를 만들어 줘. 학생 개인 식별 정보는 사용하지 말고, 만족도 변화와 계열별 응답만 분석해 줘. 표 3개와 그래프 2개를 넣고 모든 수치는 원자료와 다시 검증해 줘. 외부 자료가 필요하면 교육부·교육청 공식 자료만 사용해 줘. 파일 삭제·외부 공유·메일 발송은 하지 마.”

      14에이전트가 스스로 오류를 고칠 수도 있지만…

      Work·Claude 업무형 기능·Computer 같은 에이전트는 작업 중

      실행→결과 확인→오류 발견→수정→다시 실행

      과정을 반복할 수 있습니다.

      예를 들어 코드를 실행하다 오류가 나면 로그를 보고 다시 수정하거나, 자료가 부족하면 다른 자료를 찾아볼 수 있습니다.

      다만 이것을

      “Chat은 스스로 오류를 못 고치고 에이전트만 고친다.”

      라고 설명하면 지나친 단순화입니다.

      Chat도 대화 과정에서 오류를 수정할 수 있습니다.

      차이는 오류 수정 능력의 존재 여부라기보다,

      에이전트형 AI가 실행 과정 안에서 이런 반복 작업을 더 자율적으로 이어갈 수 있다

      는 데 있습니다.

      주의: 스스로 고치는 과정이 길어질수록 중간 단계의 잘못된 가정이 최종 결과물까지 이어질 수 있습니다. 또 반복이 많을수록 사용량·크레딧 소모도 커집니다.

      15왜 MCP라는 말을 자주 듣게 될까?

      최근 AI가

      • Google Drive
      • Gmail
      • Slack
      • GitHub
      • 사내 시스템
      • 각종 데이터베이스

      같은 외부 서비스와 연결되면서 MCP(Model Context Protocol)라는 용어를 자주 보게 됩니다.

      쉽게 말하면

      AI와 외부 도구가 서로 정보를 주고받을 수 있게 연결하는 표준 방식 중 하나

      입니다.

      추가MCP는 Anthropic이 2024년 11월 오픈 표준으로 공개한 규격입니다. 쉽게 말해 “AI용 USB 포트”처럼 AI 앱과 외부 도구를 같은 규칙으로 꽂을 수 있게 합니다. Claude의 “로컬 커넥터”, “로컬 MCP 서버를 포함한 플러그인”이라는 표현이 이것과 관련 있으며, 이런 로컬 연결은 데스크톱 앱에서만 동작합니다.

      다만 주의할 점이 있습니다.

      Work·Cowork·Computer의 모든 연결이 반드시 MCP로 이루어지는 것은 아닙니다.

      회사별 자체 커넥터·플러그인·API 등 다양한 연결 방식이 함께 사용됩니다.

      따라서

      틀림“세 서비스가 외부 앱을 사용하는 이유는 모두 MCP 때문이다.”
      맞음“MCP를 포함한 여러 연결 기술 덕분에 AI가 외부 서비스와 함께 일할 수 있게 되고 있다.”

      라고 이해하는 것이 정확합니다.

      16결국 AI 사용법 자체가 바뀌고 있다

      사람

      자료 찾기↓AI에게 질문↓다시 파일 열기↓AI에게 요약 요청↓Excel 정리↓AI에게 문장 요청↓PPT 만들기

      즉,

      사람이 일을 하고 AI가 중간중간 도왔다.

      ✓마지막 한 문장

      AI를 잘 쓰는 사람은 더 이상 질문만 잘하는 사람이 아니라,
      AI에게 ‘무엇을 맡기고, 어디까지 맡기고, 무엇은 사람이 확인할지’를 잘 정하는 사람입니다.

      3. 중요한 결과와 행동은 사람이 검수·승인한다.
